# Dedicated Playwright validation

`npm ci` then `npx playwright install chromium` installs the pinned runner and browser. `npm run test:e2e:local` serves only a small local asset allowlist and stubs every API with synthetic data. It verifies modal pointer submission, privacy/JSON/CSV downloads, WCAG A/AA automated checks and document overflow at 1440/768/390px. Local results are not live evidence. `PLAYWRIGHT_EXECUTABLE_PATH` optionally selects an installed **test** browser binary.

Live runs require a newly created, test-only profile (`E2E_PROFILE`), `PREVIEW_URL` on the isolated US Pages host, `PREVIEW_DB_VERIFIED=sst-preview-us` and `PREVIEW_TEST_CONFIRM=disposable-synthetic-workspaces`. Never use a normal Chrome profile, production origin, customer account or exported personal cookies. TLS verification and the browser sandbox stay enabled. Requests permit only Preview, Cloudflare Access and listed UI asset hosts. No Access policy or authentication implementation is changed.

Run `npm run test:e2e:authenticate`, complete Cloudflare Access manually in the headed browser, then terminate that launcher gracefully before running the suite. The new profile persists its own session privately. The live suite copies only this profile's Access authentication into isolated contexts, then redeems short-lived synthetic login/invitation tokens through the normal endpoints. No raw cookies, headers, response bodies or token URLs are included in its result log. Do not record raw traces/HARs; those contain credentials.

Use Python 3.11+ `tests/e2e/fixtures.py prepare --run sst-us-e2e-<unique-id> --deployment <verified-preview-deployment-id> --output <private-directory>` with the existing Wrangler OAuth configuration. `WRANGLER_CONFIG` can point to that configuration on another platform. The helper pins the US account/database/project, verifies the deployment binding and AI flag, creates only example.invalid synthetic identities, and suppresses welcome mail. It does not exercise email delivery. Set `E2E_FIXTURE_FILE` to its private `fixtures.json` and `E2E_DEPLOYMENT_FILE` to `deployment.json`. Run `npm run test:e2e:live` with a separate `E2E_OUTPUT`. Fixture preparation is not counted as product behavior.

The suite fails closed if synthetic login/identity verification fails. It does not change AI consent or lock settings. Existing fixture B can resume after its legacy import; that import is only tested when B is empty. A usage-reporting 503 is a failure, not a skipped/passed test. Axe checks cover the tested subscription view, not a full accessibility certification. A new browser context is independent storage, not another browser engine.

After validation, run the helper with `cleanup` and the same exact run/deployment/output. It verifies synthetic ownership, removes only enumerated fixture identities and workspaces, and verifies zero scoped rows. Delete the dedicated test profile and private manifests after closing browsers. Never commit profiles, tokens, downloads or raw traces. `test-results/`, `playwright/.auth/` and `.e2e-private/` are ignored; use a private external directory for credentials.

If Access redirects to sign-in, stop live tests and request manual authentication. Do not bypass Access. Use `npm run test:release` plus local E2E independently and distinguish their evidence.
