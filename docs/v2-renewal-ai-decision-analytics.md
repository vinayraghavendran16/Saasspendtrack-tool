# Renewal AI decision analytics
Every material recommendation must persist its revision, rationale, evidence locators and generation audit event atomically. Every rationale/evidence view, challenge, reassessment, acceptance, rejection, deferral, approval, execution and outcome recording must produce a tenant-scoped audit event. Link actions to the exact recommendation revision and canonical commercial contract; never infer contract identity from names. Validate audit event action/entity/actor correspondence before publication. Evidence locators require permission-aware digest and span verification; locator storage alone is not verification.
 
Renewal Analytics should project distinct recommendations, response rates, challenges and resolution rates, approved versus executed actions, time to decision, notice deadlines, renewal outcomes and projected versus reconciled savings. Use explicit cohort windows and denominators; distinguish no response from rejection, approval from execution, and forecast from realized outcomes. Do not count views as decisions or repeated events as separate recommendations. Preserve revision history and invalidate superseded approvals. Link verified outcomes to existing financial reviews and exclusive evidence allocation; no duplicate savings, cross-currency sums or causal attribution without evidence. Show manual versus AI-assisted action provenance. Contract-level and portfolio views must enforce tenant authorization. No learning from unverified outcomes.
 
Implementation gates: immutable recommendation publication with generation audit linkage; canonical contract binding; verified evidence resolver; action state machine and atomic audit linkage; challenge resolution and approval guards; renewal analytics projection and UI; integration tests. Default off; no production deployment.
