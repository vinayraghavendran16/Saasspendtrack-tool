# Employee intelligence
HRMS employment and IdP account status are independent facts; missing/stale data is unknown, never termination. SSO login alone is not directory synchronization. Use read-only directory APIs or authorized SCIM provisioning with explicit tenant setup. Initial adapters: Entra ID, Okta, Google Workspace, then HRMS based on customer demand. Provider scopes and field projection must be verified before enablement. No raw payload persistence, employee names, personal emails, salary, address, DOB, medical or performance data. Provider subject identifiers are HMAC-pseudonymized with tenant-separated keys, never plain email hashes. Work email for existing membership and notifications is a separate purpose-limited mapping. Pseudonymous data remains personal data. No automatic access revocation, licence cancellation or employee termination inference. Confirm HRMS departure, flag assigned licences and ownership for authorized human review. Keep employment, directory status, app assignment and usage separately timestamped. Cross-provider matching requires verified administrator mapping; no fuzzy matching. Sync failure preserves last known state with stale marker. Full reconciliation, pagination, webhook verification, deletion/retention, key rotation, secret vault and audit are mandatory before live connection. No raw payloads in logs or AI. No provider connection enabled by this specification.
